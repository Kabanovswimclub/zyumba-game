# Семейное сохранение — подготовка

Статус: облако НЕ подключено. При открытии Supabase Dashboard запрошен вход. Без участия пользователя авторизация не завершалась; текущий кабинет работает на устройстве.

Подготовлено: 001_family.sql, отдельные таблицы только Зюмбы, RLS по владельцу, составные внешние ключи исключают привязку к чужому ребёнку, закрытый bucket с ограничением типов и размера. SQL не применялся и не проверен на живой базе.

После входа пользователя:
1. Подтвердить проект «Игры» по имени и ID, проверить его состояние и существующие таблицы. Не создавать платный проект и не обращаться к базе Swim Up.
2. Проверить отсутствие конфликтов имён перед применением миграции.
3. Настроить отдельный Supabase Auth и разрешённый домен игры. Добавить клиентский publishable/anon key; service_role в браузер не помещать.
4. Подключить настоящий вход родителя и перенос выбранных локальных профилей с явным выбором, какие данные переносить. Не показывать локальный режим как облачный вход.
5. Реализовать очередь синхронизации с revision/CAS либо журналом событий: не перезаписывать молча прогресс другого устройства.
6. Фото загружать только после подтверждения сохранения, путь owner_id/child_id/photo_id.jpg, без публичных URL. Показывать через короткоживущие signed URLs.
7. До включения синхронизации проверить двумя тестовыми семьями: чужие профили/состояния/фото недоступны; анонимный доступ закрыт. Проверить обновление сессии и offline retry без дублей кормлений.

Документация: https://supabase.com/docs/guides/database/postgres/row-level-security и https://supabase.com/docs/guides/storage/security/access-control
